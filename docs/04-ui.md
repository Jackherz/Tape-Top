# UI spec — what the prototype is doing and why

The prototype lives in `ui/` (`index.html`, `ui.css`, `ui.js`). Serve it with
`python3 -m http.server 8080` from `ui/` and open `localhost:8080`.

It is a **feel prototype**: real layout, real typography, real transport state, real audio from the
engine renders. It is not the plugin's editor yet, and there is no recording.

---

## 1. What each reference board contributed

| Board | What I took | Where it shows |
|---|---|---|
| OP-1 screensheet | thin single-weight strokes on black, tiny letterspaced labels, numbers as big readouts, colour only for state (green/red/cyan), grid-and-node diagrams, the idea that a screen is an instrument panel | overall line weight, the lane grid, counters, trick icons |
| Y2K chrome star sheet | metallic glyphs as *decoration only*, never as controls | brand mark, used sparingly; text watermark idea |
| Bold logotype sheet | geometric wordmark with wide tracking; content set *into* the letterforms | `TAPE–TOP` wordmark, tagline under it |
| Lab-rack poster ("signal conditioning") | panelised modules, screw dots, cream silkscreen on charcoal, dotted matrices, long thin faders with tick marks, **coloured patch cables** as the only saturated elements | panel borders, screws, dot-matrix backdrop, faders, accent colour system |
| Retro-futurist vector pack | circular/hexagonal technical glyphs, vector-geodesic globe | knob tick rings, loop shading, scope grid |
| Pixel/glitch icon sheet | 1 px icons, "LOADING"/"ERROR" microcopy, barcode strips | trick icons, barcode in the header, "NOT FOR RESALE" footer |
| Label/print sheet (barcodes, CE marks, 製品) | density of tiny legal/industrial text, barcode strips, registration marks | header serial block, footer disclaimer, spec readout |
| MONO/PIXEL project sheet | mix of engineering diagram + typography, thin hairline rules | lane dividers, spec table |

The through-line in all eight: **cream hairlines on charcoal, with colour reserved for signal.**

## 2. Design tokens

```
--black   #0a0b09   page
--panel   #121410   panel
--silk    #e9e4d2   silkscreen / primary type
--silk-dim rgba(233,228,210,.40)   labels
--line    rgba(233,228,210,.14)    hairlines
--orange  #e2622a   primary accent (= vintage stock)
--cyan    #3fb6e8   studio stock
--green   #57c46a   porta stock
--purple  #8a6be0   disk mini stock
--red     #d8452e   record / armed
--ochre   #c9a227   meter mid
```

Rules:
- Nothing is filled unless it is a **readout** or a **state**. Controls are outlines.
- Type: a grotesque for labels (uppercase, `letter-spacing: .16–.26em`, 7–9.5 px), a monospace for
  every number. No third typeface, ever.
- One accent at a time: the system accent *is* the selected tape stock's colour, and it recolours the
  playhead, the head marker, knobs' value arcs and the scope trace.
- Motion is mechanical: reels rotate at a period proportional to 1/speed, and stop instantly when the
  transport stops. Nothing eases except the tape-stop, where the ease *is* the physics.

## 3. Layout

```
┌──────────────────────────── chrome: wordmark · tags · barcode · serial ────────────────────────────┐
│ TAPE STOCK     │  TRACKS  (8 lanes, bar/beat/step grid, loop shading, playhead)  │ MASTER          │
│ (4 styles)     │                                                               │ 3-band EQ       │
│ TRANSPORT      │                                                               │ output + meters │
│ reels · counter│                                                               │ SCOPE           │
│ keys · speed   │  TAPE TRICKS 1–8            loop in/out/toggle                 │ GLUE            │
│ STOCK SPEC     │                                                               │                 │
├──────────────────────────────────────────────── 8 STRIPS (gain knobs + meters) ──────────────────┤
│ footer: independence disclaimer · keyboard hints                                                    │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

Why this shape: the OP-1's tape screen is *horizontal time, vertical tracks*, and the tricks are a row
of eight. Keeping that geometry makes the instrument legible to someone who has used the hardware,
while the rack chrome (rails, plates, spec tables) is what makes it look like a piece of equipment
rather than a phone app.

## 4. Interaction vocabulary

| Control | Behaviour |
|---|---|
| Space | play / stop |
| 1–8 | tape tricks (press-and-hold where momentary) |
| ← / → | seek 1 s |
| Transport keys | rew · stop · play · rec(arm) · ff |
| TAPE SPEED | 0.25–2.0× varispeed; the reels' rotation rate follows it |
| TRICKS · LOOP IN / OUT / LOOP | sets loop points at the head, toggles looping |
| TRICKS · BREAK | hold to spin the transport down; release to spin back up (rate glide = tape stop) |
| TRICKS · REVERSE | flips direction; audio comes from a reversed buffer, so it is a real reverse |
| TRICKS · CHOP | engages a tempo-locked ⅛-bar loop at the head |
| TRICKS · MEMO 1 / 2 | first press stores the current stock/speed/loop, press again to recall |
| Knobs | vertical drag; value shown in both numerals and the arc |
| Lane | click to select the strip; click the T-number to arm |

Deliberately **not** in the prototype: recording, lift/drop/split/join, undo, splice crossfade.
Those need the plugin's media layer, and the point of the prototype is to decide whether the panel
has room for them.

## 5. Open design questions

1. **Eight strips + eight tricks + master** is a wide panel. On a laptop screen the mixer row is the
   first thing to squeeze — do we collapse it to a tab, or make the strips vertical (OP-1 mixer style)?
2. The lane area is the identity of the instrument. Should a lane show **takes** (regions, as now),
   **waveforms**, or **both** (waveform inside the take, as now) — and at what zoom does it switch?
3. Colour: one accent tied to the tape stock (current) is coherent, but it loses the eight-colour
   identity you get from TE's encoders. Alternative: eight track colours permanently, accent only on
   state. Worth an A/B screenshot before committing.
4. Does the wordmark stay `TAPE–TOP`, or do we name it after the transport instead ("EIGHT/FOUR",
   "REEL 8", "STOCK")? It needs to read well at 9 px in the plugin list.
